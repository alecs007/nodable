# Internationalization

Nodable ships English and Romanian. The interface picks a language from the browser on the first
visit and remembers the choice afterwards.

## Where the text lives

| Path                                      | Content                                             |
| ----------------------------------------- | --------------------------------------------------- |
| `apps/web/src/lib/i18n/en.json`           | English catalogue, and the source of the key type   |
| `apps/web/src/lib/i18n/ro.json`           | Romanian catalogue                                  |
| `apps/web/src/lib/i18n/messages.ts`       | Locale list, detection and the `translate` function |
| `apps/web/src/lib/state/locale.svelte.ts` | The active locale and the `t` helper components use |

Catalogues are flat JSON objects. A key is dot separated and lowercase, grouped by area:
`input.label`, `toolbar.negation`, `diagnostic.ndb003`, `workspace.add`.

No message text lives in `packages/engine` or `packages/sdk`. A diagnostic carries a translation
key, and the interface resolves it.

## Adding a key

1. Add it to `en.json`, in the group it belongs to.
2. Add the same key to `ro.json`.
3. Use it in a component with `locale.t('your.key')`.

`en.json` defines the `MessageKey` type and `ro.json` is typed as `Record<MessageKey, string>`, so a
key that is missing from the Romanian catalogue, or a key that only exists there, fails
`pnpm typecheck`. Keys are never built at runtime from strings; always write the whole key, so the
type checker can see it.

## Placeholders

A message may contain `{name}` placeholders, filled by the second argument:

```ts
locale.t('hint.expected', { tokens: 'a variable, ¬, (' })
```

Placeholders are replaced literally. Keep the same placeholder names in every catalogue.

## Adding a language

1. Add the code to `LOCALES` in `messages.ts`.
2. Create `apps/web/src/lib/i18n/<code>.json` with every key from `en.json`.
3. Register the catalogue in the `CATALOGS` record.
4. Add the language name to every catalogue, as `language.<code>`.

Detection matches the first two letters of each entry in `navigator.languages`, so `ro-RO` selects
Romanian. English is the fallback.

## Writing the text

- Sentence case, no trailing period on labels and hints.
- Keep button labels short; the interface relies on icons with an accessible name behind them.
- Logic symbols (`¬`, `∧`, `∨`, `→`, `↔`) and diagnostic codes (`NDB001`) are never translated.
- Identifiers, file names and code stay in English everywhere; Romanian appears only inside
  `ro.json`.
